# LayerMed — Project Rules (Permanent)

These rules govern ALL work on this project. The Head Agent (Coordinator) MUST follow these before doing anything.

---

## Rule 1: Fire Up Sub-Agents on Every Prompt
On EVERY user prompt that involves work, the Head Agent must spin up the relevant sub-agents to handle their domains. The Head Agent does NOT do coding work directly — it delegates, coordinates, and reviews.

## Rule 2: Sub-Agent Structure
There are exactly three sub-agents, plus the Head Agent:
- **Head Agent (Me):** Coordinator. Delegates tasks, reviews results, updates documentation, relays security findings.
- **Backend Agent:** Works ONLY on backend code (Django, Python, DRF, PostgreSQL, API endpoints, models, migrations).
- **Frontend Agent:** Works ONLY on frontend code (HTML, CSS, JS, Three.js, React Three Fiber, GSAP, WebGL shaders, UI).
- **Security Agent:** Audits code written by Backend and Frontend agents. Looks for bugs, errors, and vulnerabilities. Reports findings to the Head Agent. The Head Agent then commands the appropriate agent (Backend or Frontend) to fix the issues.

## Rule 3: architect.md — The Living Project Map
- The file `architect.md` in the project root contains ALL data and a full map of the project.
- Sub-agents MUST read this file FIRST before making any changes, so they don't have to search through every file.
- The Head Agent MUST update `architect.md` EVERY TIME there is a structural change (new files, new models, new endpoints, new components, directory changes, dependency changes, etc.).

## Rule 4: Major Reports
- On every MAJOR task completion or big update, the Head Agent writes a comprehensive report `.md` file (artifact).
- This report must explain the project clearly: what tools are used, how each functionality works, the current state.
- This report is NOT updated on small tweaks — only on significant milestones.

## Rule 5: Sub-Agent Capabilities
- **Backend Agent:** Has write tools (file creation, editing, commands). Uses the best model suited for backend logic.
- **Frontend Agent:** Has write tools (file creation, editing, commands). Uses the best model suited for frontend/3D work.
- **Security Agent:** Has READ-ONLY tools (file viewing, searching, grepping). It is strictly an auditor. It CANNOT write files. It reports vulnerabilities/bugs to the Head Agent, who then instructs Backend or Frontend to fix them.

---

*These rules are non-negotiable for the duration of this project.*
